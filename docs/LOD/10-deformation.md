# Спецификация требований — DeformationSystem

## 1. Назначение

Управление персистентными разрушающими изменениями планеты (кратеры,
строительство, копка, тоннели). Write-through в кэш и дифф-хранение в
persistent-слой генератора.

## 2. Связь с родительской спецификацией

| Требование | Как удовлетворяется |
|------------|--------------------|
| LOD-REQ-GEN6 | Write-through кэш. Дифф-хранение. Персистентность патчей |
| LOD-REQ-GEN2 | Исключение из round-trip для чанков с патчами |
| LOD-REQ-GEN3 | Патчи добавляются в контракт (patchIds) |

## 3. Функциональные требования

### LOD-DF-001: Применение патча
**Приоритет:** high (будущее)
**Статус:** не реализовано

`applyPatch(patch)` применяет разрушающее изменение:

1. Идентифицирует затронутые чанки (affectedChunks)
2. Для каждого чанка:
   a. Загружает базовую геометрию (процедурную или из кэша)
   b. Применяет дифф (HeightDiff[]) — добавляет deltaHeight к позициям вершин
   c. При необходимости модифицирует нормали
   d. Обновляет меш в кэше (write-through)
   e. Сохраняет патч в persistent-слой генератора
3. Обновляет контракты затронутых чанков (patchIds)

Предусловие: patch.id уникален, affectedChunks не пуст.
Постусловие: EP10 — геометрия проходит I1–I4 (кроме round-trip).

### LOD-DF-002: Реконструкция чанка с патчами
**Приоритет:** high (будущее)
**Статус:** не реализовано

`reconstruct(chunkId, baseGeometry)` восстанавливает геометрию чанка,
применяя все активные патчи поверх процедурной базы.

Вызывается при:
- Поднятии чанка после вытеснения из кэша (генератор запрашивает базу,
  DeformationSystem применяет патчи)
- Merge (родительский чанк строится из базы + патчи 4 детей)

### LOD-DF-003: Дифф-хранение (diff storage)
**Приоритет:** high (будущее)
**Статус:** не реализовано

Патч хранит только дифф относительно процедурной базы — список `HeightDiff`,
а не полную копию геометрии чанка. Это принципиально: хранение полной копии
геометрии каждого изменённого чанка сделало бы deformation несовместимым с
бесконечной процедурной планетой.

`serializePatches()` и `deserializePatches(data)` — сериализация всех патчей
в ArrayBuffer и обратно для сохранения между сессиями.

### LOD-DF-004: Нарушение round-trip
**Приоритет:** high (будущее)
**Статус:** не реализовано

`isRoundTripValid(chunkId)` возвращает false для чанков с применёнными
патчами.

Чанк, изменённый deformation, не обязан проходить round-trip (split → merge =
identical). Merge с последующим split такого чанка восстановит процедурную
базу + патчи, но из-за разницы в разрешении (глубине) результат может
отличаться — это ожидаемое поведение (LOD-REQ-GEN2 исключение).

### LOD-DF-005: Типы патчей
**Приоритет:** medium (будущее)
**Статус:** не реализовано

Поддерживаемые типы:
- `crater` — кратер (радиальное понижение высоты, поднятие края)
- `construction` — строительство (здания, площадки)
- `tunnel` — тоннель (понижение высоты под землёй, не видимое с поверхности)
- `excavation` — копка (открытое понижение высоты)
- `custom` — произвольный дифф

Тип патча влияет на поведение normal recalculation и на видимость в разных
слоях геометрии (LOD-REQ-GEN5).

## 4. Интерфейс

```ts
interface DeformationPatch {
  id: string;
  type: 'crater' | 'construction' | 'tunnel' | 'excavation' | 'custom';
  affectedChunks: string[];
  diff: HeightDiff[];
  appliedAt: number;
}

interface HeightDiff {
  localUV: [number, number];
  deltaHeight: number;
  deltaNormal: [number, number, number] | null;
  layer: 'base' | 'biome' | 'anthropogenic';
}

class DeformationSystem {
  applyPatch(patch: DeformationPatch): void;
  getPatchesForChunk(chunkId: string): DeformationPatch[];
  reconstruct(chunkId: string, baseGeometry: ChunkGeometry): ChunkGeometry;
  serializePatches(): ArrayBuffer;
  deserializePatches(data: ArrayBuffer): void;
  isRoundTripValid(chunkId: string): boolean;
}
```

## 5. Краевые случаи

- **Патч на границе чанков:** affectedChunks включает все чанки, которых
  касается дифф. Контракты на общем ребре пересчитываются после применения
- **Патч на чанке, отсутствующем в кэше:** патч сохраняется в persistent-слой,
  применяется при следующей загрузке чанка
- **Конфликт патчей:** два патча, модифицирующие одну вершину — порядок
  применения определяется `appliedAt` timestamp
- **Патч нулевого размера:** diff = [] — no-op, но patch.id регистрируется
  в контракте
- **Отмена патча:** удаление патча и реконструкция чанка (восстановление базы +
  оставшиеся патчи)

## 6. Зависимости

CacheSubsystem (write-through), ChunkGenerator (reconstruct),
BoundaryContractEngine (контракты пересчитываются после патча).

## 7. Стратегия тестирования

- **Применение патча:** создать кратер на чанке → геометрия изменена,
  deltaHeight совпадает с ожидаемой
- **Write-through:** applyPatch → чанк в кэше обновлён И патч в persistent-
  слое → evict → загрузить заново → патч применён
- **Round-trip исключение:** isRoundTripValid = false после applyPatch
- **Сериализация:** serialize → deserialize → getPatchesForChunk возвращает
  те же патчи
- **Граница чанков:** патч, пересекающий границу → оба чанка изменены,
  контракт на общем ребре всё ещё C⁰
