# Протокол интервью — развитие спецификации LOD Chunk System

**Дата:** 2026-05-08
**Участники:** разработчик (yamshchikoff), Claude Code
**Цель:** углублённое интервью для развития `docs/LOD-chunk-system.md`

## Заданные вопросы и ответы

### Q1: Асинхронность генерации чанков

**Ответ:** Асинхронность — не догма. Разгрузка в performance-critical местах,
точечная (Web Worker, offscreen), а не «всё асинхронно». Где синхронно
достаточно — остаётся синхронно.

### Q2: Слои геометрии чанка

**Ответ:** В будущем — элаймент с геоморфологическими процессами
(геоморфологический софт, генеративные модели). Геометрия будет состоять
из слоёв и объектов. Чанк станет произвольно гибким: строительство, копка
шахт, тоннели, терраморфирование, горные работы и т.д. Монолитный меш —
временное решение.

### Q3: Кубическая сфера vs другие проекции

**Ответ:** Искажений на полюсах не должно быть ни при какой реализации.
Это достигается не выбором проекции, а тем, что чанк заявляет на своей
границе как контракт. Проекция — деталь реализации за контрактом.

### Q4: Стратегия инвалидации кэша при deformation

**Ответ:** Write-through. Патч пишется в кэш и одновременно в
persistent-слой генератора. При вытеснении из кэша данные не теряются —
генератор поднимает чанк уже с патчем.

### Q5: Контракты помимо геометрических

**Ответ:** Контракты на:
- Время генерации (чанк depth d — не более N ms)
- Память
- Seed-детерминизм
- Типизированные по содержимому (каньон, дорога, направление градиента
  геологических параметров)
- Добавки от патчей (тоннель, ж/д, ЛЭП, городская засветка)

### Q6: Полярные чанки

**Ответ:** Полярный чанк (face ±Y) на каждом из четырёх рёбер объявляет
контракт, с которым обязаны совпасть соседние чанки экваториальных граней
(faces ±X, ±Z). Внутренняя геометрия полярного чанка — деталь реализации
за контрактом: может быть другая тесселляция, более густая сетка у полюса,
радиальная вместо квадратной. Контракт должен включать условие сходимости
четырёх граней в точке полюса (единственная топологическая сингулярность).
Никакого специального механизма «полярной шапки» не требуется.

Визуальная верификация: spawn на полюсе и дебаг сходимости рёбер визуально.

## Итоги интервью

Интервью завершено. Выявлены 6 архитектурных решений:
1. Точечная асинхронность в performance-critical местах
2. Слоистая геометрия чанка (геоморфология, стройка, копка)
3. Контракт на границе важнее проекции — искажения недопустимы
4. Write-through кэш для deformation-патчей
5. Контракты расширены: время, память, seed, типы содержимого, патчи
6. Полярные чанки: контрактная сходимость без специального механизма

Все решения подлежат внесению в `docs/LOD-chunk-system.md`.
